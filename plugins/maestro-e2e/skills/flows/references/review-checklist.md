# 기존 Flow 리뷰

`.maestro/` 아래 Flow와 subflow를 읽고 아래 항목을 본다. 저장소의 `.claude/skills/`나 문서에 규칙이 따로 있으면
그것이 우선이다. 리뷰는 보고까지만 한다. 고치는 건 사용자가 요청하면 한다.

## 보고 형식

항목마다 `파일:줄`, 무엇이 문제인지, 왜 깨지는지, 고친 예를 한 줄씩 적는다. **깨짐**(지금 틀렸거나 곧 불안정해진다)을
먼저, **정리**(중복·이름)를 뒤에 둔다. 문제가 없으면 없다고 적는다. 본 파일 수도 함께 적는다.

## 깨짐

**시작과 앱 상태**

- `runFlow: ../subflows/launch_clean.yaml`(또는 그 저장소의 공통 시작 subflow)로 시작하지 않는다.
- Flow 중간에 `launchApp: { clearState: true }`나 `clearState`를 직접 쓴다. Android에서 옛 태스크 정리가 새 프로세스를
  죽이는 레이스가 난다(`gotchas.md`). 공통 subflow를 부른다.
- `appId`에 값을 박아 두었다. 플랫폼마다 값이 달라 한쪽에서만 돈다. `${APP_ID}`를 쓴다.
- `launchApp`에 `permissions`가 없다. 기본값 `all: allow`가 Android에서 APK 전체를 매번 받는다.

**찾기**

- 화면 문구로 찾는다(`tapOn: "로그인"`, `assertVisible: "Settings"`). 기기 언어가 바뀌면 깨진다. id로 바꾼다.
  통화 코드·숫자처럼 언어와 무관한 글자는 괜찮다.
- 좌표(`point:`)나 `index:`로 찾는다. 화면 크기와 목록 순서가 바뀌면 다른 요소를 누른다.
- id에 정규식 특수문자가 있다(`keypad.+`). `id:`는 전체 일치 정규식이다.
- 글자 단언의 `.`을 이스케이프하지 않았다(`"0.25"` → `"0\\.25"`).
- 단언하는 글자가 화면의 다른 글자와 겹친다(결과 `"7"`이 키패드 7에 잡힌다).

**기다림**

- 요소를 기다리지 않고 누른다. 앞 단계가 화면을 바꾸는데 다음 단계가 바로 찾는다.
- 나타나지 않을 id를 `optional`로 기다려 시간을 버는 단계가 공통 subflow 밖에 있다. 고정 대기라 느린 기기에서 모자라고
  빠른 기기에서 낭비다. 다음 화면의 요소를 `extendedWaitUntil`로 기다린다.
- 이유 없이 긴 `timeout`. 원인을 가린 흔적일 수 있다. 커밋 기록이나 주석에 이유가 없으면 묻는다.
- `optional: true`가 본 단계에 붙어 있다. 실패해도 통과하므로 그 단계는 검사하지 않는 것과 같다.

**단언**

- 끝에 결과를 확인하는 `assertVisible`·`assertNotVisible`이 없다. 누르기만 하고 끝나면 앱이 틀려도 통과한다.
- 매일 바뀌는 값(환율, 날짜, 잔액)을 값으로 단언한다. 형식을 정규식으로 본다.

**태그와 범위**

- 태그가 `smoke`·`release` 둘 중 하나가 아니거나 둘 다 붙었다(그 저장소의 기준이 따로 있으면 그것을 따른다).
- `smoke`가 서버 응답, 로그인, 결제에 기댄다. CI에서 서버 상태에 따라 떨어진다.
- 광고를 누르거나 실제 광고를 노출한다. 무효 트래픽이다.
- 되돌릴 수 없는 동작(결제, 탈퇴, 운영 데이터 변경)을 한다.
- 계정·비밀번호를 Flow에 적어 두었다. `-e`와 CI 변수로 넘긴다. 로그인 단계가 여러 Flow에 복사돼 있으면 subflow로 뺀다.

**플랫폼**

- `back`을 `when: { platform: Android }` 없이 쓴다. iOS에는 없다.
- 한 플랫폼에만 있는 id를 조건 없이 쓴다.

## 정리

- 같은 단계 묶음이 세 Flow 이상에 복사돼 있다. `subflows/`로 빼고 `runFlow`로 부른다.
- subflow가 `config.yaml`의 `flows:`에 잡혀 단독 테스트로 돈다.
- 파일 이름이 그 저장소의 규칙(예: `smoke_<흐름>.yaml`)과 다르다.
- `name:`이 없거나 무엇을 확인하는지 드러나지 않는다.
