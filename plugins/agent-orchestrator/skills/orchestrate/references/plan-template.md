# 계획 산출물 형식

구현자는 이 파일만 읽고 일한다. 대화 맥락을 모른다고 보고 쓴다.

`## 건드릴 파일` 아래 첫 코드 블록은 `scope-guard.sh`가 파싱한다. 제목과 블록 형식을 바꾸지 않는다.
`## 검증`은 코드 블록을 여러 개 써도 된다. **전부 돈다.**

## 템플릿

```markdown
# <작업 이름>

작성: <누가> / <날짜>
대상: <파일이나 영역>
근거: <무엇을 읽고 썼는지 — 문서·소스·앞선 리뷰>

## 목적

한 문단. 무엇을 확인하거나 바꾸려는 것인지. 고치는 작업인지 사실을 확인하는 작업인지 분명히 한다.

## 위험도

`low` / `medium` / `high` 중 하나만 적는다. 적지 않으면 `medium`으로 본다.

- `high` — 인증·결제·개인정보·배포 설정·DB 마이그레이션에 닿는다. 공개 API를 바꾼다
- `medium` — 여러 파일이나 계층이 함께 바뀐다
- `low` — 한 파일 안에서 끝나고 되돌리기 쉽다

높을수록 자동 수정 횟수가 줄어든다. high 1회, medium 2회, low 3회.
사람이 변경 이력을 따라갈 수 있게 하려는 것이다.

## 조사로 확인한 구조

| 사실 | 근거 |
| --- | --- |
| ... | `파일:줄` |

읽어서 안 것만 적는다. 추측은 다음 절에 둔다.

## 가설

사실 확인 작업일 때만. 번호를 붙이고, 어느 것이 이 작업으로 확정될지 밝힌다.

## 할 일

## 건드릴 파일

```
경로를 한 줄에 하나씩
폴더째 열려면/끝에 슬래시를 붙인다/
```

이 목록 밖의 파일을 바꾸면 범위 위반이다.
**끝이 `/`인 줄만 디렉터리로 본다.** 슬래시가 없으면 파일 하나다 —
`presentation`이 모듈 전체를 조용히 여는 것을 막으려는 것이다.
에셋 폴더처럼 파일이 여럿 생기는 자리는 슬래시를 붙여 한 줄로 적는다.

## 지킬 것

프로젝트 규칙 중 이 작업에 걸리는 것만 옮긴다. 규칙 문서를 통째로 베끼지 않는다.
대신 읽어야 할 파일 경로를 준다.

## 쓰지 말 것

## 검증

```
<명령>
```

```
<명령이 여럿이면 블록을 나눠도 된다. 전부 돈다>
```

**계획에 적기 전에 한 번 돌려 본다.** 안 돌아가는 명령을 적으면 구현자가 거기서 막힌다.
이 명령들이 다른 파일을 건드리지 않는다는 것도 적어 준다. 안 그러면 구현자가 조심하느라 건너뛴다.
한 줄에 하나씩 적는다. 블록을 몇 개로 나누든 **적힌 순서대로 전부** 돌고, 하나라도 실패하면 거기서 멈춘다.

## 이 작업으로 확인할 수 없는 것

생략하지 않는다. 이게 없으면 결과가 실제보다 넓게 읽힌다.
도구가 없어서 못 보는 것, 범위를 넘어서 안 보는 것을 나눠 적는다.

## 완료 조건

- 기계가 판정할 수 있게 쓴다
- 사실 확인 작업이면 "가설이 확정되거나 반증된다"가 조건이다. "테스트가 통과한다"가 아니다
- 커밋 여부를 명시한다
```

## 자주 틀리는 곳

- **"통과시켜라"로 읽히게 쓰는 것.** 사실 확인 작업에서는 "틀렸으면 틀렸다고 드러나는 테스트를 써라,
  통과시키려고 프로덕션을 고치지 마라"를 명시한다. 안 쓰면 구현자가 통과를 목표로 삼는다
- **규칙을 다 옮겨 적는 것.** 길어지면 구현자가 중요한 줄을 놓친다. 걸리는 것만 적고 나머지는 경로로 준다
- **확인할 수 없는 것을 안 적는 것.** 리뷰어가 가장 먼저 잡는 구멍이다
- **폴더를 슬래시 없이 적는 것.** `Assets.xcassets/Common` 은 파일 하나로 읽혀서,
  그 안에 생긴 파일이 전부 범위 위반이 된다. 폴더는 `Assets.xcassets/Common/` 으로 적는다
