# ui-contract

디자인 수치를 계약 파일로 고정하고, 그 계약대로 UI를 구현하고 검증합니다.
Compose·SwiftUI·Flutter를 다루며 특정 디자인 도구에 묶이지 않습니다.

## 왜 필요한가

이미지 한 장을 주고 "똑같이 만들어줘"라고 하면 결과는 늘 미묘하게 틀립니다.
AI가 UI를 못 짜서가 아니라 **이미지에는 수치가 없기 때문**입니다.

```text
카드 width가 343인지 344인지
padding이 16인지 20인지
line-height가 22인지 24인지
shadow opacity가 8%인지 12%인지
```

사람도 확대하지 않으면 헷갈리는 값입니다. 디자인 파일에는 이 정보가 이미 있습니다.
문제는 그것을 **구현자가 어길 수 없는 형태로** 넘기는 일입니다.

## 두 단계로 나눕니다

| 스킬 | 하는 일 | 하지 않는 일 |
| --- | --- | --- |
| `extract` | 디자인 소스에서 수치를 뽑아 계약 파일을 만든다 | **코드를 쓰지 않는다** |
| `implement` | 계약 기준으로 구현하고 검증한다 | 계약에 없는 수치를 만들지 않는다 |

수치가 틀리면 그 위에 올린 구현은 계속 흔들립니다. 그래서 수치를 먼저 고정합니다.

## 처음 한 번

```bash
claude plugin install ui-contract@ahn-cc-kit
```

**"이 피그마 화면 구현해줘"** 또는 `/ui-contract:extract`를 요청합니다.
AI가 디자인 데이터를 읽어 네 파일을 만듭니다.

```text
.ui-contract/<화면이름>/
├── layout-contract.json    크기·padding·gap·radius — 구현이 쓸 수 있는 유일한 수치 출처
├── design-tokens.json      색·타이포그래피·radius·shadow, light/dark
├── component-map.md        디자인 컴포넌트 ↔ 코드 컴포넌트
└── ambiguity-report.md     판단이 필요한 것
```

사람이 `ambiguity-report.md`를 읽고 답한 뒤 **"계약대로 구현해줘"**로 넘어갑니다.

## 어떤 입력을 받나

| 가진 것 | 동작 |
| --- | --- |
| Figma·Zeplin MCP | layout 데이터를 직접 읽습니다 |
| Dev Mode 복사값·스펙 문서 | 온 값만 채우고 나머지는 `null`로 둡니다 |
| 스크린샷뿐 | **계약 파일을 만들지 않습니다.** 추측이라고 알리고 디자인 데이터를 요청합니다 |

마지막 줄이 이 플러그인의 핵심입니다.
이미지에서 뽑은 값에 계약 파일의 형식을 입히면, 나중에 읽는 사람은
그것이 측정값인지 추측인지 구별할 수 없습니다.

## pixel perfect가 아닙니다

iOS와 Android는 폰트 렌더링·line-height 처리·anti-aliasing이 달라
스크린샷이 완전히 같아질 수 없습니다. 같게 만들려고 수치를 비틀면 오히려 계약에서 멀어집니다.

```text
나쁜 목표   디자인 이미지와 100% 똑같이 보이게 만든다
좋은 목표   계약된 수치·토큰·매핑을 지키고 허용 오차 안에서 통과시킨다
```

허용 오차와 리뷰 출력 형식은
[validation.md](skills/implement/references/validation.md)에 있습니다.

## 다른 플러그인과의 경계

- **`context-pack`** — 작업 범위, 수정 금지 파일, 완료 보고 형식은 그쪽이 정본입니다.
  같이 쓰면 `task.md`에 범위를 적고 계약 파일을 `files.md`에서 가리킵니다
- **`agent-orchestrator`** — 계획·구현·리뷰를 갈라 돌리는 왕복 절차는 그쪽이 정본입니다.
  이 플러그인은 그 왕복에서 오가는 **산출물의 내용**만 정합니다
- **`android-review`** — Kotlin·Compose 코드 품질을 봅니다.
  이 플러그인은 **수치가 계약과 맞는지**를 봅니다. 축이 다릅니다
- **Figma MCP** — 디자인 데이터를 **가져옵니다**.
  이 플러그인은 그 데이터를 **검증 가능한 계약으로 고정합니다.**
  `get_design_context`가 내놓는 코드는 참조일 뿐 최종 코드가 아닙니다

## 요구 사항

없습니다. 디자인 MCP가 붙어 있으면 수치를 직접 읽고, 없으면 사람이 준 값으로 동작합니다.
스크린샷 검증은 프로젝트에 이미 있는 방법을 씁니다 — 없는 프로젝트에 새로 만들지 않습니다.
