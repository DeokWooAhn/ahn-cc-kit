# context-pack

작업 전에 AI가 필요한 맥락을 작성하고, 정한 경계와 검증 기준으로 일하게 합니다.
특정 언어·플랫폼·CI에 의존하지 않습니다.

## 처음 한 번

```bash
claude plugin install context-pack@ahn-cc-kit
```

프로젝트에서 **"이 프로젝트에 컨텍스트팩 도입해줘"** 또는 `/context-pack:setup`을 요청합니다.
AI가 기존 지침·계획·검증 경로를 조사하고 아래 파일을 구성합니다.

```text
AGENTS.md 또는 CLAUDE.md          짧은 자동 작성 진입 규칙
.context-pack/
├── workflow.md                   작업별 작성·구현·검증 절차
├── integrations.md               다른 kit와 역할을 나누는 기준
├── project.md                    이 프로젝트의 지침·스킬·검증 원본 경로
└── templates/                    작업 문서 다섯 개의 양식
```

개인 도입을 요청하면 `CLAUDE.local.md`에 연결합니다. 그 파일을 읽지 않는 도구에는 적용되지 않으므로
개인 지침 로딩을 확인해야 합니다. 팀 지침이나 전역 설정으로 개인 규칙을 옮기지 않습니다.
팀 공통 도입 파일을 커밋·배포할지는 프로젝트 관례와 사용자 요청을 따릅니다.

## 그다음부터

평소처럼 **"결제 버튼 중복 요청 버그 고쳐줘"**라고 요청합니다. 별도로 팩 작성을 지시할 필요가 없습니다.
AI는 프로젝트 지침에 따라 관련 코드·규칙·기존 계획을 확인하고 다음을 **내용까지 작성**합니다.

```text
context/<작업명>/
├── task.md       문제·기대 동작·제외 범위·근거와 미확인 사항
├── files.md      읽기·수정·생성 허용 범위, 별도 허가 영역
├── rules.md      관련 규칙·결정·중단 조건
├── tests.md      시나리오·명령·환경·실제 결과와 한계
└── done.md       완료 조건·범위 대조·결과 보고
```

팩 위치와 계획을 알리고 구현·검증합니다. 마지막에는 diff와 결과를 완료 기준에 대조하고,
변경하지 않은 주요 경계도 보고합니다. 질문·읽기 전용 리뷰에는 구현용 팩을 만들지 않습니다.
사소한 변경은 다섯 항목을 채팅으로 축약합니다. 팩만 요청하면 구현하지 않습니다.
기존 작업 메모·계획은 정본으로 재사용하고 다섯 문서에서 해당 절을 연결할 수 있습니다.

**자동화는 지침 기반입니다.** 파일을 작성했다고 모델의 준수나 테스트 성공을 기계적으로 보증하지 않습니다.
보안 차단은 guard, 테스트·E2E 관문은 해당 도구와 CI가 맡습니다. 이 플러그인은 훅·외부 모델·MCP 서버·새 CI를 추가하지 않습니다.
도입 뒤 절차는 프로젝트에 남아 직접 읽을 수 있습니다. 플러그인 업데이트가 복사본을 자동 갱신하지 않으며,
업데이트하려면 AI가 기존 보완 사항과 새 절차의 차이를 검토해 병합합니다.

## 기존 kit와 조합

| 대상 | 연결 방식 |
| --- | --- |
| `agent-orchestrator`·다른 계획 실행기 | 네이티브 계획이 정본. 다섯 문서는 해당 절을 연결하며 범위·승인·스냅샷 계약 유지 |
| `maestro-e2e`·프로젝트 검증 스킬 | `tests.md`에서 실행 절차와 실제 결과 파일 연결. 별도 Stop 훅 없음 |
| 프로젝트 리뷰·`android-review` | 기존 리뷰 기준을 연결. 검토만 요청받으면 팩 생성·코드 수정 없음 |
| `git-guard`·`android-guard`·외부 guard | 기존 차단·권한 유지. 팩의 허용 범위로 우회하지 않음 |
| `explain-diff` | 설명을 요청받았을 때만 연결. 완료 보고마다 설명 페이지를 만들지 않음 |

상세는 [조합 기준](skills/pack/references/integrations.md)에 있습니다.

## 생성 스크립트

Python 3.9 이상. 플러그인 루트에서 실행합니다. AI의 판단을 대신하지 않고 파일 준비만 합니다.

```bash
python3 scripts/context_pack.py setup --project /path/to/project --instructions AGENTS.md
python3 scripts/context_pack.py new --project /path/to/project --task checkout-duplicate-submit
```

- `setup`: 절차·템플릿과 진입 규칙을 준비합니다. AI가 `project.md`를 채우고 기존 메모·독립된 도구 진입점을 정리해야 도입이 끝납니다.
- `new`: 빈 양식만 만듭니다. 도입 전에도 단독으로 쓸 수 있고, 루트 지침을 바꾸지 않습니다.
- 기존 파일·팩은 덮어쓰지 않습니다. 불완전한 기존 팩·잘못된 연결 표식·프로젝트 밖으로 향하는 링크는 실패로 보고합니다.
- `--instructions` 생략 시 새 프로젝트·단일 지침·명시적인 `@AGENTS.md` 연결만 자동 선택합니다.
  두 정본 후보가 독립적이면 조사 후 명시해야 합니다.

## 검증

```bash
python3 -m unittest discover -s plugins/context-pack/tests -v
claude plugin validate plugins/context-pack
```

위 명령은 ahn-cc-kit 루트에서 실행합니다. 생성기의 보존·경로 안전성과 패키징을 확인합니다.
모델 행동 점검은 [시나리오](tests/scenarios.md)를 따로 사용하고, 실행 여부를 구분해 보고합니다.

새 Claude 세션에서 도입 → 설명만 요청 → 일반 버그 수정까지 실제 실행했습니다.
수정 세션에는 팩 작성을 다시 지시하거나 플러그인을 별도로 로드하지 않았습니다.
다섯 문서 작성이 구현보다 앞섰고 모델의 테스트 8개와 별도 검증 10개가 통과했습니다.
[행동 검증 결과와 재현 방법](tests/behavioral-results.md)에 환경·권한·확인 한계를 기록했습니다.
