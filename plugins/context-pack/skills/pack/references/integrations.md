# 기존 절차와 함께 쓰기

Context Pack은 작업 맥락을 정리한다. 다른 도구가 맡은 실행·차단·리뷰를 복제하지 않는다.
설치된 플러그인 이름만 보고 활성화하지 말고 현재 요청과 프로젝트 설정을 확인한다.

## 기존 메모·계획

- 기존 작업 메모가 있으면 이어 쓴다. 새 팩은 다섯 문서에서 그 메모의 해당 절을 연결하는 방식으로 구성할 수 있다.
  목표·허용 파일·검증 조건의 정본을 두 벌 만들지 않는다. 부족한 항목만 원본에 보완한다.
- 원본의 소유자·권한·구조를 확인한다. 개인 계획을 팀 지침에 복사하지 않는다.
- 커밋할 문서와 로컬 산출물은 프로젝트 관례를 따른다. `.gitignore`나 전역 설정을 임의로 고치지 않는다.

## agent-orchestrator 또는 다른 계획 실행기

- 사용자가 그 실행기를 선택한 작업에서만 결합한다. 팩 작성 때문에 에이전트를 나누거나 `orch`를 실행하지 않는다.
- 네이티브 계획을 정본으로 삼고 다섯 문서는 해당 절을 가리킨다. `scope-guard`의 `## 건드릴 파일` 형식과
  런타임의 승인·역할·재시도 계약을 바꾸지 않는다. 별도의 허용 파일 목록을 운영하지 않는다.
- 팩을 위임·스냅샷 **전에** 준비한다. 스냅샷 이후 구현자는 팩을 고쳐 자신의 범위를 넓히지 않는다.
  새 근거 때문에 변경이 필요하면 계획 소유자가 원본을 갱신하고 실행기의 승인·스냅샷 절차를 따른다.
- 독립 리뷰를 요청받았으면 그 kit의 리뷰 브리프 계약을 따른다. 작성자의 성공 결론을 리뷰 근거처럼 넘기지 않는다.

## Maestro·테스트·검증 kit

- `tests.md`에 프로젝트의 실행 스킬·명령과 결과 파일을 연결한다. 기기 선택, 테스트 모드, smoke/release 구분,
  결과 JUnit, 건너뛰기·실패 처리와 배포 관문은 해당 kit가 정한다.
- Maestro 훅이 요구하는 실제 결과를 팩의 "완료" 문장으로 대체하지 않는다. 같은 Stop 훅을 추가하지 않는다.
- 앱의 두 플랫폼·공유 모듈·서버 계약이 걸리면 관련 검증을 골라 연결한다. 모든 프로젝트에 같은 전체 테스트를 강제하지 않는다.

## 리뷰·설명·보안 kit

- 프로젝트 전용 리뷰 기준을 먼저 연결한다. 범용 `android-review` 같은 kit의 체크리스트를 팩에 통째로 복사하지 않는다.
- `explain-diff`는 사람이 변경을 이해하도록 요청받았을 때 쓴다. 완료 보고를 자동으로 HTML 설명 페이지로 만들지 않는다.
- `git-guard`·`android-guard`·외부 guard의 권한과 판정을 유지한다. 팩의 허용 목록은 guard를 우회할 근거가 아니다.
  감사·보안 검토도 요청이나 실제 필요가 있을 때 해당 kit에 맡긴다.

## 전역 규칙과의 관계

프로젝트 전체 규칙은 루트 지침·전문 스킬·결정 문서에 둔다. 팩은 이번 작업의 선택과 근거만 담는다.
추가 도구·유료 서비스·운영 접근·강제 Git 조작을 도입의 전제로 만들지 않는다.
