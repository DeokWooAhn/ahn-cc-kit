# Context Pack 도입

한 번 도입하면 다음 변경 요청부터 AI가 필요한 팩을 준비한다. 루트 지침은 시작점을 알려 주고,
프로젝트 안에 복사한 절차는 플러그인을 사용할 수 없는 도구에서도 직접 읽을 수 있게 한다.

## 조사

1. 루트 `AGENTS.md`, `CLAUDE.md`, `CLAUDE.local.md`가 있으면 읽는다. import·링크도 직접 확인해
   **실제 정본**을 찾는다. 두 지침이 독립적이거나 브랜치별 정본이 다르면 파일명만으로 정하지 않는다.
2. 기존 작업 메모·계획 위치, 관련 스킬·결정 문서의 목차, 검증 명령·CI, 사용하는 다른 kit를 확인한다.
   앱 전체나 모든 스킬을 읽지 않고 도입에 필요한 경로만 조사한다.
3. 팀 공통 규칙이면 팀 정본에, 개인 도입을 요청받았으면 개인 지침에 연결한다.
   개인 도입에서는 팀 파일·전역 설정을 고치지 않는다. 개인 지침을 읽지 않는 도구에는 자동 적용되지 않음을 알린다.

## 도입

1. 바꿀 지침과 생성할 파일, 기존 메모를 재사용할 방법을 짧게 설명한다. 사용자에게 이미 받은 도입 권한으로 진행하되
   프로젝트에 별도 승인 규칙이 있으면 따른다. 모든 작업마다 새 승인을 요구하는 규칙을 추가하지 않는다.
2. 이 플러그인의 `scripts/context_pack.py`를 찾아 다음을 실행한다. `<plugin>`은 `skills/setup/`에서 두 단계 위다.

   ```bash
   python3 "<plugin>/scripts/context_pack.py" setup --project "<project>" --instructions AGENTS.md
   ```

   `--instructions`는 조사한 정본에 맞춰 `AGENTS.md`, `CLAUDE.md`, `CLAUDE.local.md` 중 고른다.
   스크립트는 `.context-pack/`에 절차·프로젝트 안내·템플릿을 복사하고 지침에 시작 규칙을 연결한다.
   기존 파일은 덮어쓰지 않는다. 재실행은 설치 확인이며 자동 업그레이드는 아니다.
3. `.context-pack/project.md`를 **실제 조사한 경로**로 채운다. 규칙 정본, 기존 계획 위치, 관련 스킬과 결정 목차,
   검증 원본·CI 경로를 연결한다. 플랫폼별 명령은 원본에 두며 프로젝트 고유 규칙을 kit에 역복사하지 않는다.
4. 기존 작업 시작 메모와 겹치는 루트 항목은 하나의 진입점으로 합친다. 기존의 근거·불확실성·권한·갱신 규칙을 보존한다.
   팀 지침과 개인 지침의 소유권을 넘기지 않는다. 다른 도구의 진입 파일이 정본을 읽는지도 확인한다.
   독립된 `CLAUDE.md`가 정본을 읽지 않으면 새 절차에 대한 짧은 경로 안내만 연결한다.
5. `.context-pack/integrations.md`를 읽어 기존 계획·오케스트레이터·Maestro·리뷰·guard와 역할을 나눈다.
   외부 kit에 동등한 절차가 있으면 그것을 정본으로 연결하고 같은 정책을 두 벌 만들지 않는다.

## 확인

- 루트 지침에서 `.context-pack/workflow.md`를 찾을 수 있고, 프로젝트 안내의 경로가 실제로 존재하는지 확인한다.
- 임시 폴더에서 `new` 명령으로 다섯 문서를 생성해 본다. 빈 템플릿 생성과 AI의 내용 작성을 구분한다.
- 다음 작업의 흐름을 설명한다: **관련 근거 조사 → 팩 작성 → 구현 → 검증 → 완료 기준 대조**.
  질문에는 팩을 만들지 않고, 사소한 변경은 같은 핵심 항목을 채팅으로 축약한다.
- 지침 기반 자동화이며 명령을 차단하는 보안 관문이 아님을 설명한다. 플러그인 설치·도입을 이유로
  커밋·푸시·배포·운영 접근 권한을 추가하지 않는다.

도입만 요청받았다면 여기서 끝낸다. 예시 작업을 명분으로 앱 코드나 CI를 바꾸지 않는다.
