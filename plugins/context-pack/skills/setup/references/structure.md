# 무엇을 어디에 두나

문서를 나누는 기준은 주제가 아니라 **언제 필요한가**다.
주제로 나누면 "이것도 관련 있으니까" 하고 루트 지침이 계속 길어진다.

| 자리 | 넣는 것 | 판별 질문 |
| --- | --- | --- |
| 루트 지침 | 어떤 작업이든 걸리는 규칙 | 이걸 모르고 코드를 고치면 틀리나? |
| `.claude/skills/` | 특정 작업에서만 필요한 절차 | 어떤 작업을 할 때만 펼치면 되나? |
| 결정 기록 | 코드에 남지 않는 판단과 그 이유 | 코드를 다 읽어도 왜 그런지 모르나? |
| 개인 파일 | 작업 스타일·응답 취향 | 다른 사람에게도 적용되나? 아니면 개인 것이다 |

같은 내용을 두 곳에 두지 않는다. 한 곳을 정본으로 두고 다른 곳에서는 경로로 가리킨다.
정본이 둘이 되면 한쪽만 고쳐지고, 어느 쪽이 맞는지 아무도 모르게 된다.

## 진입점을 어떻게 가르나

**누가 이 저장소를 읽는지**가 결정한다. 파일 이름 취향이 아니다.

| 상황 | 배치 |
| --- | --- |
| 스킬 자동 로드가 없는 에이전트(Codex, 리뷰 봇 등)와 함께 쓴다 | `AGENTS.md`가 본체, `CLAUDE.md`는 브리지 |
| Claude Code만 쓴다 | `CLAUDE.md`가 본체 |
| 개인 작업 스타일 | `CLAUDE.local.md` (git 미추적) |

브리지는 세 줄이면 된다. 어디에 본체가 있는지와 왜 그렇게 했는지, 그리고 import 한 줄이다.

```markdown
# CLAUDE.md

이 저장소의 에이전트 지침은 <다른 도구>와 같이 쓰려고 AGENTS.md 한 곳에 둔다. 내용은 거기서 고친다.

@AGENTS.md
```

반대 방향(`CLAUDE.md`가 본체)이면 `AGENTS.md`에 같은 역할의 짧은 안내를 둔다.
import 문법은 도구마다 다르므로 상대 도구가 실제로 읽는지 확인하고 적는다.

생성기가 브리지를 만들었다면 `@AGENTS.md` 한 줄만 들어 있다. **왜 그렇게 나눴는지 한 줄을 위에 더한다.**
`@AGENTS.md`는 줄 단위로 판별하므로 설명을 앞에 붙여도 정본 자동 판별이 깨지지 않는다.
반대 방향의 `AGENTS.md` 브리지는 생성기가 내용 전체를 비교해 정본을 가리므로 **한 글자도 바꾸지 않는다.**
설명을 더하고 싶으면 본체인 `CLAUDE.md` 쪽에 적는다.

**두 파일이 독립적으로 긴 내용을 담고 있으면 합치기 전에 사용자에게 묻는다.**
한쪽이 팀 정본이고 다른 쪽이 개인용일 수 있다. 소유권을 넘기는 변경을 임의로 하지 않는다.

## 스킬로 내리는 기준

루트 지침의 한 절이 열 줄을 넘고, 그 내용이 특정 작업에서만 필요하면 스킬 후보다.

- `description`에 **언제 불려야 하는지**를 쓴다. 무엇을 하는지만 쓰면 트리거가 걸리지 않는다.
- 스킬 `description`은 매 세션 컨텍스트에 올라간다. 안 쓰는 스킬을 늘리면 그만큼 다른 것을 밀어낸다.
  쓰지 않는 스킬은 지우는 편이 낫다.
- 긴 절차는 `SKILL.md`를 짧게 두고 `references/`로 내린다. 모델은 `SKILL.md`를 항상 읽고
  `references/`는 필요할 때만 읽는다.

**스킬 자동 로드가 없는 도구도 같은 저장소를 읽는다면**, 루트 지침의 `## 세부 문서` 표에
상황과 파일 경로를 남긴다. 그 도구는 표를 보고 직접 연다. 이 표가 있어야 스킬을 쓰면서도
한 벌의 문서로 두 종류의 독자를 받을 수 있다.

## 결정 기록을 둘지 정하는 법

코드에 남지 않는 판단이 쌓이는 프로젝트에만 만든다. 다음이 하나라도 해당하면 필요하다.

- 스토어 문구·이미지·소개 글처럼 코드 밖에서 정하는 것이 있다
- "버그처럼 보이지만 일부러 그렇게 한" 동작이 있다
- 하지 않기로 한 선택(쓰지 않을 라이브러리, 열지 않을 기능)이 반복해서 다시 논의된다

만든다면 목록 README를 함께 둔다. **언제 읽나 / 언제 쓰나 / 형식** 세 절이면 충분하다.
파일 하나에 결정 하나를 담고, 주제로 이름을 짓는다. 결정을 바꿀 때는 새 파일을 만들지 않고
기존 기록을 고친 뒤 변경 이력을 남긴다. 그래야 "예전에 반대로 정했던 것"이 보인다.

코드를 고칠 때마다 알아야 하는 규칙과 함정은 결정 기록이 아니라 루트 지침과 스킬에 둔다.
