# 루트 지침의 절

루트 지침은 규칙 저장소가 아니라 **길잡이**다. 매 작업에 걸리는 것만 두고 나머지는 경로로 보낸다.
길어지면 중요한 줄이 묻힌다. 한 절이 열 줄을 넘으면 스킬이나 문서로 내릴 후보다.

아래는 절의 **차례와 각 절이 답해야 할 질문**이다. 모든 절이 모든 프로젝트에 필요하지는 않다.
해당 사항이 없는 절은 빈 채로 두지 말고 뺀다.

| 절 | 답할 질문 | 뺄 수 있는 경우 |
| --- | --- | --- |
| 머리말 | 무슨 앱인가, 누가 이 파일을 읽나, 세부는 어디에 | 없음 |
| 작업 방식 | 기본 동작이 무엇이고 어디서 멈춰 물어야 하나 | 없음 |
| 작업 시작 메모 | 코드를 고치기 전에 무엇을 정리하나 | 팩을 쓰지 않기로 한 프로젝트 |
| 브랜치·커밋·PR | 어디서 갈라 어디로 합치나 | 혼자 쓰는 저장소 |
| 안전장치 | 무엇이 기계적으로 막히나 | 보호 설정도 훅도 없을 때 |
| 보안 | 무엇을 커밋·로그에 남기면 안 되나 | 없음 |
| 프로젝트 구조 | 레이어·모듈 경계가 어떻게 되나 | 단일 파일 수준의 작은 저장소 |
| 쓰지 않는 것 | 새로 들이지 않을 기술이 무엇인가 | 금지 항목이 없을 때 |
| 검증 | 무엇을 어떻게 돌려 확인하나 | 없음 |
| 릴리스·배포 | 어떻게 내보내나 | 배포 대상이 없을 때 |
| 환경 함정 | 코드만 봐서는 모르는 것이 무엇인가 | 겪은 함정이 없을 때(생기면 추가) |
| 세부 문서 | 어떤 상황에 무엇을 읽나 | 스킬도 문서도 없을 때 |

## 절별로 자주 빠뜨리는 것

**머리말** — 누가 읽는지를 적는다. 스킬 자동 로드가 없는 에이전트가 함께 읽는다면
그 사실이 파일 구조 전체를 정한다. 읽는 쪽이 바뀌면 구조도 다시 본다.

**작업 방식** — 기본값을 먼저 정한다. 예를 들어 "요청이 없으면 읽기·설명만 한다"처럼
가만히 있을 때의 동작을 적는다. 그다음 무엇을 할 때 확인을 받는지 적는다.
**실행하지 않은 검증을 통과했다고 말하지 않는다**는 줄은 어느 프로젝트에나 넣을 값이 있다.

**안전장치** — 보호 설정에는 **날짜와 근거**를 적는다(`ruleset 이름`, 적용일).
설정이 바뀌면 지침도 바뀌어야 하는데, 근거가 없으면 무엇이 낡았는지 알 수 없다.
필수 검사가 걸려 있지 **않다면** 그 사실도 적는다. 걸려 있다고 착각하는 편이 더 위험하다.
설치된 훅은 무엇을 막는지와 **막혔을 때 어떻게 하는지**까지 적는다 — 우회하지 않고 알린다.

**보안** — 공개 저장소인지 먼저 밝힌다. 공개 여부가 나머지 판단을 바꾼다.
커밋 금지 항목과 **커밋해도 되는 것**을 함께 적는다. 둘을 구분해 두지 않으면
설정 파일 하나 추가할 때마다 멈춰 묻게 된다.

**쓰지 않는 것** — 지금 위반이 있는지 없는지 밝힌다. "현재 위반 없음"이라고 적어 두면
새로 들어온 것인지 원래 있던 것인지 바로 갈린다. 금지 이유도 한 줄씩 붙인다.
이유 없는 금지는 "이번에는 괜찮겠지"로 넘어간다.

**환경 함정** — 증상 → 원인 → 대신 쓸 명령 순으로 적는다.
"`build`를 쓰지 마라"가 아니라 "`build`는 로컬에서 실패한다, 시크릿을 강제 검증하기 때문이다,
일반 검증에는 이것을 쓴다"로 적는다. 이유를 알면 응용하고, 모르면 우회한다.

**세부 문서** — 파일이 아니라 **상황**을 먼저 적는다. 읽는 쪽은 파일명을 모르고 상황만 안다.

| 상황 | 읽을 파일 |
| --- | --- |
| 코드 리뷰, PR·diff 검토 | `.claude/skills/review/SKILL.md` |

## 한시적 규칙

지금만 필요한 규칙에는 **언제 지우는지**를 함께 적는다.

> 이 분기를 본 브랜치에 합치면 이 항목과 위 목록의 해당 줄, 그리고 관련 설정 파일의
> 같은 줄을 함께 지운다.

이게 없으면 끝난 규칙이 남아 다음 작업을 틀리게 만든다. 지울 조건과 **함께 지울 곳**까지 적는다.
