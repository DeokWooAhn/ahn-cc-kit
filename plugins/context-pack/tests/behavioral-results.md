# 새 AI 세션 행동 검증 결과

2026-11-17, Claude Code 2.1.317의 기본 모델 `claude-opus-5-5`로 실제 실행했다.
실제 앱 대신 Python 표준 라이브러리로 된 임시 재고·주문 프로젝트를 사용했다.
각 호출은 `--no-session-persistence`, 자동 메모리 끄기, 이어받기 없는 별도 세션이다.

| 세션 | 사용자 요청 | 확인 결과 |
| --- | --- | --- |
| 도입 | 프로젝트에 context-pack 도입 요청 | `context-pack:setup`을 스스로 호출. 기존 지침에 진입 규칙 연결, 실제 경로로 프로젝트 안내 작성. 앱·테스트·CI·기존 사용자 메모 보존 |
| 설명 | checkout과 inventory의 역할 설명만 요청 | 팩·파일 생성이나 수정 없음. 파일 해시가 세션 전후 동일 |
| 수정 | 실패한 주문이 이미 재고를 차감하는 버그와 수량 검사 수정 요청 | 팩 작성 재지시 없이 다섯 문서를 내용까지 작성한 뒤 코드·회귀 테스트 수정·검증. 문서의 검증 결과·완료 대조 갱신 |

도입 때만 `--plugin-dir`로 이 플러그인을 로드했다. 다음 두 세션의 초기화 기록에는 `context-pack`이 없고,
프로젝트의 지침·복사된 절차만으로 작동했다. CLI 내장 플러그인은 기본 환경으로 유지됐다.
세션 식별자는 모두 다르며 모델에 이전 대화나 검증 정답을 전달하지 않았다.

## 구현·검증 근거

- 파일 변경 관찰과 도구 호출 기록에서 팩 다섯 문서의 내용 작성이 첫 앱·테스트 수정보다 앞선 것을 확인했다.
- `files.md`가 재고·주문·관련 테스트·이번 팩만 수정 허용으로 지정했다. 실제 diff도 그 범위 안이었다.
- 모델이 표준 `unittest` 명령을 직접 실행했다. 기존 2개와 추가 6개, 총 8개 테스트가 통과했다.
- 모델에 주지 않은 별도 검증은 수정 전 실패했고 수정 후 10개 시나리오가 통과했다.
  뒤 항목 실패·없는 상품·중복 상품 합계 초과·0/음수 수량·정상 반환·빈 주문을 확인했다.
- 기존 사용자 메모와 수정 제외 상품 파일은 해시가 그대로였다.
- 팩의 사실·제외 범위·규칙 원본·검증 명령·실행 결과·확인 한계·완료 대조도 직접 읽어 확인했다.

## 권한과 확인 한계

권한 질문을 받지 않는 실행 환경에서 일부 복합 셸 명령은 거절됐다. 모델은 허용된 읽기·파일 편집·검증 도구로 진행했고
거절된 명령을 성공으로 보고하지 않았다. 도입 세션의 별도 `/tmp` 견본 생성 확인은 미실행으로 보고했다.
생성기 자체의 동작은 별도 단위 검사에서 확인했고, 실제 작업 팩은 수정 세션에서 생성·작성됐다.

이 결과는 위 임시 프로젝트·모델·도구 권한에서의 한 번의 실행 근거다. 모든 모델·외부 kit 조합·플랫폼에서의 준수를 보증하지 않는다.
기존 계획 재사용·개인 도입·원본 보존·경로 안전성은 문서 계약 검토와 별도 단위 검사로 확인했다.
실제 앱 저장소·운영 서비스·전역 설정에는 도입하지 않았다.

## 재현

ahn-cc-kit 루트에서 다음을 실행한다. Claude 로그인이 필요하고 실제 모델 호출이 발생한다.
최대 3개 세션에 각각 4달러 사용량 상한을 둔다. 일반 CI에서는 실행하지 않는다.

```bash
python3 plugins/context-pack/tests/run_behavioral_eval.py --output /path/to/new-result-directory
```

원본 대화에는 로컬 경로·도구 메타데이터가 포함될 수 있어 Git에 넣지 않는다.
