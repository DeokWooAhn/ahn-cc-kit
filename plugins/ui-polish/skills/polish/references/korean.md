# 한국어 화면

원본의 값은 영문 기준이다. 그대로 쓰면 한글에서 다르게 보인다.

## 굵기

**영문 기준으로 "굵기를 낮춰라"를 한글에 그대로 적용하지 않는다.**

한글은 획이 많아 같은 굵기에서 영문보다 빽빽해 보이고, 반대로 얇은 굵기에서는
작은 크기일 때 먼저 뭉개진다. 한글 글꼴은 굵기 단계 자체가 적은 경우도 있다.

- 제목에서 700을 500으로 낮추면 영문에서는 단정해지지만 한글에서는 위계가 사라질 수 있다
- 본문을 300·200 같은 얇은 굵기로 두면 작은 크기에서 읽기 어렵다
- **실제 글꼴에 그 굵기가 있는지 먼저 확인한다.** 없으면 플랫폼이 합성해서 그리고,
  그렇게 그린 글자는 다르게 보인다

바꾸기 전에 지금 글꼴이 어떤 굵기를 갖고 있는지 보고, 바꾼 뒤 **실제 화면에서 비교한다.**

## 줄바꿈

한글은 단어 중간에서도 줄이 바뀐다. 그대로 두면 낱말이 쪼개져 읽기가 끊긴다.

| 플랫폼 | 확인할 것 |
| --- | --- |
| Compose | `TextStyle`의 `lineBreak`. CJK 어절 단위는 `LineBreak.WordBreak.Phrase` |
| SwiftUI | 대체로 알아서 처리한다. 좁은 폭에서 실제로 보고 판단한다 |
| Flutter | 기본은 문자 단위로 끊긴다. 어절 단위가 필요하면 따로 처리한다 |

짧은 라벨일수록 눈에 띈다. **버튼과 탭 이름을 좁은 폭에서 본다.**

## 줄 높이

받침 때문에 한글은 같은 글자 크기에서 영문보다 세로로 넉넉한 줄 높이가 필요하다.
영문 예시의 `fontSize : lineHeight` 비율을 그대로 쓰면 줄이 붙어 보인다.

## 길이

같은 뜻이라도 한국어 UI 문구는 영어보다 길어지는 경우가 많다.
영문 기준으로 잡은 버튼 폭과 라벨 자리에서 **줄바꿈이나 말줄임이 생기는지** 본다.

반대로 지나치게 줄이면 뜻이 사라진다. "완료"가 저장 완료인지 발주 완료인지
맥락으로만 알 수 있다면 동사를 남기는 편이 낫다.

## 숫자

금액·수량처럼 **세로로 비교하는 숫자 열에는 고정폭 숫자를 쓴다.**
글자마다 폭이 다르면 자릿수가 어긋나 보여서 비교가 느려진다.

| 플랫폼 | 방법 |
| --- | --- |
| Compose | `TextStyle(fontFeatureSettings = "tnum")` |
| SwiftUI | `.monospacedDigit()` |
| Flutter | `TextStyle(fontFeatures: [FontFeature.tabularFigures()])` |

**글꼴이 지원하는지 먼저 확인한다.** 지원하지 않으면 적용해도 바뀌지 않는다.
숫자만 다른 글꼴로 바꾸는 것은 대개 더 나쁘다.

## 문구

- **문체를 섞지 않는다.** 한 화면 안에서 "~합니다"와 "~해요"가 섞이면 눈에 띈다.
  프로젝트에 정해진 문체가 있으면 그것을 따른다
- **조사가 붙는 동적 문구를 조심한다.** 이름이나 숫자 뒤에 "을/를", "이/가"가 붙으면
  값에 따라 틀린 조사가 나온다. 문장 구조를 바꿔 피하는 편이 안전하다
- **기간과 기준을 남긴다.** "12% 증가"에 비교 대상이 없으면 짧아진 만큼 정보가 사라진 것이다
- 제목에는 막연한 수식 대신 **기간이나 대상 이름**을 쓴다

## 검수

- 가장 긴 이름과 가장 큰 숫자를 넣어 본다
- 글자 크기를 키운 상태에서 본다
- 좁은 기기에서 버튼과 탭 라벨이 쪼개지지 않는지 본다
- 오류 문구가 여러 줄이 될 때 레이아웃이 버티는지 본다
